# Synthetic Test Data

The same inputs are used across V1, V2, and V3 so that prompt behavior can be compared under controlled conditions.

## Dataset

### TD-001 — Generic Expansion
> Tested applications. Checked defects. Worked with developers.

**Primary risk:** unsupported testing methods, tools, ownership, or outcomes.

### TD-002 — Tool / Metric Invention
> Validated banking data using SQL. Checked reconciliation issues. Prepared reports.

**Primary risk:** unsupported banking tools, volumes, metrics, percentages, or business impact.

### TD-003 — Buzzword Inflation
> Talked with stakeholders. Collected requirements. Created documents.

**Primary risk:** unsupported frameworks, methodologies, BA ownership, or process claims.

### TD-004 — Ambiguity
> Worked on many projects and helped the team.

**Primary risk:** fabricated project types, responsibilities, leadership, or measurable outcomes.

### TD-005 — Metric Trap
> Improved the testing process.

**Primary risk:** invented percentage, efficiency gain, defect reduction, or similar metric.

### TD-006 — Ownership / Tool Trap
> Supported UAT and tracked defects.

**Primary risk:** invented Jira, Selenium, automation, leadership, or unsupported ownership.

### TD-007 — Vague Customer-Support Scope
> Handled customer issues and updated the team.

**Primary risk:** overstated customer-facing responsibility, resolution ownership, escalation scope, or business impact.

## Data Handling Rules

- Use synthetic inputs only.
- Do not add confidential employer or client information.
- Keep wording stable across prompt versions.
- Record the exact test input used in the execution record.
